# Hermes 待办桌宠单机正式版设计

## 产品边界

正式版第一阶段只服务一名用户和一台 Windows 电脑。应用不要求账号，不连接 Hermes、飞书或真实 Agent，不提供具体时间安排，只处理日期级待办。

## 已确认交互规则

- Windows 登录后自动启动，默认显示桌宠入口。
- 面板失焦、手动收起或关闭时继续驻留托盘；只有托盘“退出”才结束程序。
- 今日待办由今天的手动待办、今天命中的周期计划条目和所有未完成逾期条目组成。
- 逾期条目保留原日期，不复制；完成时直接更新原始记录。
- 今日排序为：逾期待办、今日周期待办、今日手动待办、已完成。
- 周期计划直接保存确定日期的条目，不在桌面端运行重复规则引擎。
- 手动计划内容使用普通文本或 Markdown，保存为 `generic.note` 内容块。
- 结构化健身、学习内容仍由现有专用或通用内容块组件展示。

## 数据结构

普通待办新增 `date: YYYY-MM-DD`。旧数据缺少日期时，从 `createdAt` 的本地日期迁移。

主进程保存一个应用状态文档：

```ts
interface StoredAppStateV1 {
  schemaVersion: 1;
  todos: unknown[];
  cyclePlans: unknown[];
  settings: {
    launchAtLogin: boolean;
  };
  updatedAt: string;
}
```

周期计划继续使用已经定稿的 v2 `CyclePlan + CyclePlanEntry + PlanContentBlock`，不再建立另一套计划模型。

## 文件仓储

正式数据保存在 Electron `app.getPath("userData")/data/state.v1.json`。

- 写入时先写 `state.v1.tmp`，再原子替换正式文件。
- 每次有效修改前备份当前正式文件。
- 只保留最近 7 份备份。
- 正式文件损坏时按时间倒序尝试备份。
- 主进程只存取应用状态，不理解健身或学习内容块。
- renderer 通过 preload 的安全 IPC 加载与保存数据，不直接访问文件系统。
- 浏览器 Demo 继续使用 `localStorage`，便于 5178 前端预览。

## 日期刷新

renderer 使用独立日期 hook：

- 启动时读取本地日期。
- 午夜后自动刷新。
- 窗口重新获得焦点、页面恢复可见时重新检查。
- 电脑休眠恢复后也会通过焦点或可见性事件纠正日期。

## 周期计划编辑

“手动添加”打开右侧编辑抽屉：

- 计划字段：标题、主题、说明。
- 条目字段：日期、标题、摘要、Markdown 详情。
- 支持增加和移除多个日期条目。
- 保存后生成 `active` 计划和 `pending` 条目。
- 新建内容块使用 `kind: generic.note`、`format: markdown`。
- 编辑已有结构化条目时保留未知内容块，不把专业 JSON 覆盖成文本。

## Windows 生命周期

- 使用单实例锁，防止重复启动。
- 托盘菜单使用中文：打开待办、隐藏、打开数据目录、导出数据、导入数据、退出。
- 正式包启用开机启动；开发模式不修改系统启动项。
- 启动时面板收起为桌宠；浏览器 Demo 保持展开便于调试。

## 导入导出

- 导出直接保存完整 `state.v1.json` 副本。
- 导入前校验顶层版本和数组字段。
- 导入前备份当前状态。
- 导入成功后通知 renderer 重新加载。
- 导入失败只提示错误，不修改当前数据。

## Windows 打包

使用 `electron-builder` 生成 NSIS 安装包和便携版。安装包默认创建快捷方式，卸载应用时不主动删除 `userData`，保留个人数据。

## 测试与验收

- 文件仓储：首次创建、原子写入、7 份备份、损坏恢复、导入校验。
- 日期逻辑：今日、逾期、未来、完成状态和排序。
- 周期计划：Markdown 草稿生成、结构化内容保留、计划 upsert。
- Electron：IPC 白名单、单实例和托盘命令通过模块级测试覆盖。
- 完整运行 `npm test`、`npm run typecheck`、`npm run build` 和 Windows 打包。
- 源码文件继续不超过 220 行。
