# AI 对话与提案工作流

## 目标

AI 页面用于讨论周期任务并生成可确认的数据变更，不是通用聊天工具。当前流程为：

`自然语言讨论 → 信息补充 → 严格 JSON → message 或 proposal → 人工确认 → 原子写入`

## 模型返回合同

模型始终返回 `AiMutationProposal v1` JSON。应用按 `operations` 分类：

- `operations: []`：作为自然语言 `message` 显示，不创建或清除已有提案。
- `operations` 非空：作为 `proposal`，进入操作预览与整批确认。
- 非法 JSON、未知字段、越权操作和超过 50 项操作会在主进程拒绝。

信息不足时每次只追问一个问题。只有用户明确要求创建或调整且信息充分时，模型才能给出写操作。模型无法绕过确认直接修改本地数据。

## 长对话规则

- 对话上下文预算为 `32,000` 字符。
- 始终保留首次用户目标和预算内最近的完整消息。
- 不截断单条消息，也不额外调用模型进行摘要。
- AI 会话、未发送输入和未确认提案只在当前应用会话保留，重启后清除。

## 界面规则

- 宽屏与紧凑模式都采用全宽单栏对话，不常驻展示技术上下文。
- 空对话使用“开始规划”聚焦引导，并提供三条与当前创建或调整场景对应的建议。
- 点击建议只填入受控输入草稿，不自动发送，也不会立即产生模型调用。
- 消息列表独立滚动，输入区固定在对话页底部。
- 输入框高度为 `44–120px`，超出后内部滚动。
- `Enter` 发送，`Shift+Enter` 换行，中文输入法组合期间不会误发送。
- 用户停留底部时跟随新回复；上翻时保持位置并显示“跳到最新”。
- 标题栏提供“操作范围”入口，按需说明可操作对象、数据发送和人工确认边界。
- 操作范围只使用用户可理解的说明，不显示 ID、`updatedAt` 等内部字段。

## 安全边界

- API Key 仅由 Electron 主进程保存和使用，不进入 renderer、日志或模型上下文。
- 应用展示配置中的真实模型名称，不采信模型对自身身份的回答。
- 所有正式写入仍通过统一批量执行器校验、克隆、原子保存或整批回滚。
